# 3H (tritium): the element scripting runtime

**3H** is HyperNix's isotope-named extension of Hydrogen. It reads editable .hnx element files and adapts their supported hooks into ordinary Hydrogen Element classes that can be registered, dependency-resolved and attached to chat.

The name refers to tritium, hydrogen-3 (³H). In HyperNix, **3H is a runtime/isotope extension, not a new chemical element**: it does not add an entry to the 118-element periodic table or change atomic numbers.

## Why an interpreter

A .hnx file is editable UTF-8 source text. 3H reads its format header and JSONL records, parses the script body into an abstract syntax tree, validates the allowed syntax, and evaluates that tree with a small custom interpreter.

There is no native compilation step or generated native binary. 3H does not call Python compile(), eval() or exec() on .hnx source. It uses Python's AST parser to obtain a syntax tree, then interprets only approved nodes.

The language combines familiar pieces:

- **Python-like:** expressions, lists, dictionaries, arithmetic, comparisons and return.
- **TypeScript-like:** function, let, const, var, true, false, null, &&, || and strict-equality spellings.
- **C++-inspired:** typed function signatures and variable declarations, including std::string.
- **JSONL:** element metadata and named data records.

This is a small scripting language, not a complete implementation of Python, TypeScript or C++.

## Loading pipeline

1. Read the version header: `#!hnx 1.1.0`.
2. Read exactly one element JSONL record and any additional data records.
3. Validate the symbol, permissions, groups and mandatory dependency array as a Hydrogen ElementSpec.
4. Normalise the brace-based syntax and parse it into an AST.
5. Reject unsupported syntax, then interpret the approved hook functions.
6. Register the generated Hydrogen element class.
7. Let Hydrogen resolve transitive dependencies; Natural Gas attaches the selected elements to the oven.

The interpreter exposes hook arguments, local values, a local data mapping and a small set of helper functions. It does not provide a general filesystem, network, process or shell API.

## Create and inspect

3H ships inside the HyperNix elements package; there is no separate compiler to install.

~~~bash
hnx elements list
hnx elements list --json
hnx elements info 3H
hnx elements new Na --format hnx
~~~

The scaffold is written beneath ~/.hypernix/elements/ by default. Its filename is derived from the periodic-table element name. Edit it with any text editor, then select it using hnx chat --elements PATH.

## Where it fits

| Module | Responsibility |
|---|---|
| hydrogen.py | Base API, registry, dependency graph, activation and permissions. |
| carbon.py | User-file discovery, legacy Python loading and 3H loader integration. |
| isotope_3h.py | Isotope descriptor, .hnx parser, validator, interpreter, class adapter and scaffolder. |
| chat_elements.py | Resolves --elements paths, group roots and default chat selection. |
| natural_gas.py | Activates and attaches the selected set to one oven, then releases it on detach. |

The runtime's file-format version (1.1.0) is separate from Hydrogen's Python hook ABI generation (GENERATION = 1). Changing the disk grammar does not automatically mean that the base Python element hooks changed.

## Execution model and limits

The current language is intentionally bounded:

- Top-level code must consist of supported hook definitions. Imports, decorators, classes and arbitrary top-level execution are rejected.
- Hook signatures cannot use default values or variadic arguments.
- Statements include local assignment, typed assignment, expression statements, return, pass and if / else if / else.
- There are no loops, exception handlers, file operations, subprocess calls, network clients or dynamic imports.
- Calls must target an allow-listed helper or a supported method on a string, list or dictionary.
- JSONL data is copied into a local mapping for each hook call; mutating that copy does not rewrite the source file or persist state.

Invalid files are recorded by Carbon and skipped so one malformed script does not stop neighbouring elements from loading. If a specifically selected file fails, chat reports the load error rather than silently selecting another element.

The restricted interpreter is a guardrail, not a promise that arbitrary hostile text is harmless in every future version. Review element packages and keep HyperNix updated.
