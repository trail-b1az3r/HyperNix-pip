# C4 — explode a model, measure its pieces, reap the best, sow a new one

`hypernix.c4` (0.72.8a2) takes a model apart, finds out what each piece
is worth, and builds a new model from the pieces worth keeping. It runs
on your GPU (CUDA, then Apple MPS, then the CPU) and reads:

| Weights | Needs |
|---|---|
| `.safetensors` (a folder, one file, or a sharded set) | a `config.json` beside it |
| `.pt` / `pytorch_model.bin` state dict | a `config.json` beside it; loaded without running code from the file |
| `.gguf` (any llama.cpp or HyperNix type) | nothing: its metadata says the same things |

## The pieces

| Piece | What it is |
|---|---|
| **mstem** | A layer and its connections: every stem of one transformer block. What c4 drops, keeps or transplants. |
| **stem** | One connection and its parameters: one weight tensor, e.g. a block's `ffn_up`. The embeddings, head and final norm are stems with no mstem. |
| **Pdial** | Three or more parameters taken together: a row (one neuron's incoming weights), a column, an attention head, a block. |
| **mdial** | Two parameters, to ask whether they matter more together than apart. |
| **dial** | One parameter. |

Nothing is copied to explode a model: pieces are addresses into the
loaded weights, written `blk.3.ffn_up.weight[12, 40]` (a dial),
`…[12, 40]+[12, 41]` (an mdial), `…[12, :]` (a row Pdial).

## The sections

```python
from hypernix import c4

ex = c4.explode.explode("./my-model")                    # on the GPU
prober = c4.probe.Prober.for_model(ex.model, texts=passages)

layers = c4.stem.layer_report(ex, prober)                 # which layers are needed
scores = c4.dial.score(ex, prober, kind="taylor")        # which weights matter
cut    = c4.dial.unneeded(scores, fraction=0.2)          # the 20% that do least, per stem
todo   = c4.dial.train_priority(ex, scores, granularity="pdial")   # what to train first

harvest = c4.reap.reap(ex, report=layers, drop_layers=2, unneeded=cut, ffn_keep=0.75)
c4.sow.sow(harvest, "./my-model-c4", explodeds=[ex], prober=prober)
c4.sow.heal("./my-model-c4", prober.calibration, steps=100)
```

**`hypernix.c4.explode`** — the pieces, their counts, iterators over a
stem's Pdials (`by="row" | "col" | "head" | "block"`), mdials and dials,
addresses, and `save()`: one safetensors file per mstem plus a manifest,
so a layer can be loaded without the rest of the model.

**`hypernix.c4.stem`** — *measured* (weights only): spread, outliers,
sparsity, kurtosis, effective and stable rank (on the GPU, sketched for
very large stems), the cost of a 4-bit round trip, and how alike two
layers are. *Tested* (running the model): the loss change when a stem or
a layer is taken out, and each layer's block influence (one minus the
cosine between the hidden state entering and leaving it). `layer_report`
ranks every layer and calls it `unneeded` (the model is better without
it), `candidate to drop`, `needed` or `keep`.

**`hypernix.c4.dial`** — a score per parameter: `magnitude`, `taylor`
(|w·g|, what removing it costs), `fisher` (g², how sensitive the loss
is), `wanda` (|w|·‖x‖). `unneeded()` picks the lowest share and lists
rows that can go whole; `train_priority()` ranks stems, Pdials or layers
by how much one more training step would lower the loss (‖g‖²/n), and
flags the ones that *need retraining* (a gradient large for their
weights); `interaction()` measures whether an mdial's two weights act
together.

**`hypernix.c4.restore`** — `Snapshot` and the `ablated()` context
manager put every tested piece back exactly (the tests leave the model
as they found it); `write()` writes safetensors (with config and
tokenizer), `.pt` or GGUF.

**`hypernix.c4.reap`** — chooses what the new model is made of: the best
layers (or all but the unneeded), the unneeded dials to zero, and the
feed-forward channels to keep (a channel's `ffn_gate`/`ffn_up` rows and
`ffn_down` column go or stay together). `reap_best()` cherry-picks across
several same-shaped models: at every depth, the donor whose layer scored
best. A `Harvest` saves as JSON plus a masks file, to review or edit
before sowing.

**`hypernix.c4.sow`** — builds the new model: the chosen layers
renumbered, unneeded dials zeroed, channels pruned, `config.json`
rewritten (`num_hidden_layers`, `intermediate_size`, per-layer lists),
tokenizer copied. It loads the result back to check it is whole and,
given a prober, reports the loss before and after. `heal()` trains it
for a few steps with the c4 optimizer.

## The c4 optimizer

Not for ordinary training: for retraining what `train_priority` picked
and for healing a sown model. `C4Optimizer` back-propagates, then
**separates** the gradients into sections (stems, mstems, or each stem's
rows) and **checks** each before anything updates:

* a non-finite gradient skips that section, not the whole step;
* a gradient norm far above the section's own history is clipped back;
* a section with no gradient for a while is frozen;
* unneeded dials are held where they are;
* only the sections you name move (`only=`), each scaled by its priority.

Then the inner optimizer updates:

| `kind` | Inner optimizer |
|---|---|
| `hybrid` (default) | `C4HybridAdamW5S` — AdamW's moments and decoupled weight decay, the step damped by Pressure Cooker V5S's three-band oscillation score, bounded by a trust ratio, with V5S's coordinate freeze. |
| `v5s` | `C4CookerV5S` — Pressure Cooker V5S with pressure diffusion off (it would blend updates across Pdial boundaries), no global clip (sections are clipped one by one), quicker coordinate freezing, and held dials kept out of its momentum. |
| `adamw` | `torch.optim.AdamW`, for comparison. |

```python
opt = c4.optim.C4Optimizer.for_exploded(ex, model_module, kind="hybrid", lr=1e-4,
                                        granularity="pdial", only=[p.piece for p in todo])
```

## Command line

```bash
hnx c4 explode MODEL --save ./pieces
hnx c4 stem MODEL --test --calib calib.txt
hnx c4 dial MODEL --calib calib.txt --score taylor --unneeded 0.2 --priority pdial
hnx c4 reap MODEL --calib calib.txt --drop 2 --unneeded 0.2 --ffn-keep 0.75 -o harvest
hnx c4 reap --best A B C --calib calib.txt -o harvest
hnx c4 sow harvest -o ./new-model --heal 100 --calib calib.txt
hnx c4 restore MODEL -o ./model-pt --format pt
```

`--calib` is a text file read with the model's own tokenizer (blank
lines separate passages). Without it the tests run on random tokens and
say so: good for checking the machinery, not for deciding what to cut.
`--json` prints JSON; `--device` picks the GPU.

## Limits

* Running the model (every *tested* number, scores other than
  `magnitude`, healing) needs `transformers` and an architecture it can
  build. A GGUF is run through transformers' GGUF loader (llama,
  mistral, qwen2/3, phi3, gemma…); one it cannot build is still
  exploded, measured, reaped and sown, by its weights alone.
* A GGUF loaded to run takes Hugging Face tensor names; write it as
  safetensors and `hnx convert` it back.
* Weights are held in float32 by default: a 7B model needs about 28 GB
  on the GPU (`dtype=torch.bfloat16` halves it).
* The GPU paths were exercised on CPU in the test suite; no GPU was
  available where it was written.
